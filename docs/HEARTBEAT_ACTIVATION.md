# تفعيل Heartbeat للتجديدات والتنبيهات

## الحالة الحالية

المعالج جاهز محلياً في المسار `POST /api/scheduled/recurring-billing`. يتحقق من هوية مهمة cron عبر `sdk.authenticateRequest`، ويرفض أي طلب عادي، ثم يشغل بشكل متوازٍ إنشاء مسودات فواتير التجديد المستحقة ومزامنة تنبيهات المنصة.

| المكوّن | الحالة | الضمان |
|---|---|---|
| مسار Express | جاهز | مسجل قبل مسارات الواجهة داخل `server/_core/index.ts`. |
| مصادقة cron | جاهزة | يتطلب `isCron` و`taskUid` ويرفض غيرهما برمز 403. |
| إنشاء الفواتير | جاهز | يستدعي `generate_due_recurring_invoices`؛ تمنع قاعدة البيانات التكرار لكل اشتراك وفترة. |
| مزامنة التنبيهات | جاهزة | تستدعي `sync_platform_notifications` في التنفيذ نفسه. |
| تفعيل الجدولة | مؤجل للنشر | يتطلب رابط إنتاج منشوراً؛ بيئة التطوير غير قابلة للاستدعاء من Heartbeat. |

## خطوة التفعيل بعد النشر

بعد أن يضغط مالك المشروع على **Publish**، تنشأ مهمة Heartbeat على مستوى المشروع بتوقيت يومي في قطر. التعبير الزمني المقترح هو `0 0 1 * * *` بالتوقيت UTC، أي 04:00 صباحاً بتوقيت قطر (UTC+3). تحفظ قيمة `task_uid` الناتجة في سجل التشغيل أو توثيق المشروع لاستخدامها لاحقاً في المراقبة أو الإيقاف.

> لا تُنشأ المهمة قبل النشر؛ لأن Heartbeat يستدعي عنوان الإنتاج فقط. يجب بعد إنشائها مراجعة سجل أول تنفيذ للتأكد من إنشاء عدد صحيح من مسودات التجديد والتنبيهات.
