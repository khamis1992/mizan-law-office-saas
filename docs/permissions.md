# مصفوفة الصلاحيات

يُطبَّق الفصل بين المكاتب في قاعدة البيانات من خلال **Row Level Security**؛ فلا يُرجع أي استعلامٍ عادي إلا سجلات المكتب المرتبط بالمستخدم. وتُضبط عمليات إنشاء السجلات أو تعديلها بالسياسات والدوال ذاتها، وليس بإخفاء أزرار الواجهة فقط.

| الوظيفة | مدير المكتب | محامٍ | موظف |
|---|---:|---:|---:|
| إدارة بيانات المكتب والدعوات | كامل | عرض فقط | عرض فقط |
| إنشاء القضايا وتحديثها | كامل | للقضايا المسندة أو التي ينشئها | عرض فقط |
| جدولة الجلسات وتسجيل النتائج | كامل | كامل | عرض فقط |
| العملاء وسجل التواصل | كامل | كامل | إضافة ومتابعة |
| المهام | كامل | كامل | تحديث المهمة المسندة إليه فقط |
| المستندات | كامل | كامل | رفع ومراجعة ملفات المكتب بحسب السياسات |
| المساعد القانوني والمذكرات | كامل | كامل | غير متاح |
| التقارير | كامل | عرض | عرض |

> يجب أن يراجع مدير المكتب هذه الصلاحيات عند إضافة أي شاشة أو إجراء جديد؛ حماية البيانات تعتمد على سياسات Supabase لا على منطق الواجهة وحده.

## الدوال الحساسة وسياسات RLS

تستخدم السياسات ثلاث دوال محددة: `current_office_id` و`is_manager` و`is_lawyer_or_manager`. تعمل هذه الدوال بوضع `SECURITY DEFINER` لتجنّب الاستدعاء الذاتي لسياسات جدول الملفات الشخصية عند تقييم العزل بين المكاتب. لا تُمنح هذه الدوال لـ `anon` أو `public`، وتقتصر على المستخدم المسجل (`authenticated`)؛ كما تتحقق من وجود `auth.uid()` قبل إرجاع أي قيمة. يجب عدم إضافة أي دالة جديدة بهذا الامتياز دون: تحديد `search_path`، سحب صلاحية `public`، وتطبيق اختبار عقدي لسياسة الاستدعاء.
