# الفواتير الضريبية والتحصيل

## نطاق الوحدة

تظهر وحدة **الفواتير الضريبية** داخل لوحة Super Admin فقط. يمكن للمسؤول إصدار فاتورة لمكتب مشترك، وتسجيل بند اشتراك وقيمته ونسبة الضريبة، ثم تسجيل تحصيل يدوي نقدي أو مرجعي مؤقت. لا تتاح للمكاتب صلاحية تغيير الفاتورة أو التحصيل، لكنها تستطيع قراءة فواتيرها الخاصة وفق سياسة عزل `office_id`.

> النظام يقدم بنية فاتورة وحساب ضريبة قابلين للضبط، ولا يحدد أو يقرّ نسبة ضريبية قانونية. تُراجع نسبة الضريبة والرقم الضريبي ومحتوى الفاتورة مع محاسب أو مستشار ضريبي مؤهل قبل الإصدار أو التقديم الرسمي.

| المرحلة | السلوك |
|---|---|
| الإعداد | يضبط Super Admin اسم الجهة المصدرة وعنوانها وبيانات الاتصال والرقم الضريبي وبادئة رقم الفاتورة ونسبة الضريبة الافتراضية. |
| المراجعة والإصدار | ينشئ النظام رقم فاتورة متسلسلاً كمسودة، ويمكن تعديل وصف البند ومبلغه ونسبته الضريبية وتاريخ الاستحقاق والملاحظات، ثم يعتمد Super Admin المسودة لإصدارها. |
| التحصيل | يسجل التحصيل النقدي المؤقت مع مرجع اختياري بعد اعتماد الفاتورة فقط، ويخصم المدفوع من الرصيد تلقائياً. |
| الحالة | تصبح الفاتورة مدفوعة جزئياً أو مدفوعة بالكامل تلقائياً، ويُمنع التحصيل فوق الرصيد. |
| PDF | زر **PDF** ينشئ ملف PDF عربياً قابلاً للتنزيل باسم رقم الفاتورة، ويضم رقم الفاتورة والحالة ومرجع التحصيل والإجماليات. |

## الحماية والتدقيق

يحفظ النظام بنود الفاتورة والمدفوعات منفصلة عن الإجماليات، ثم يعيد حساب الإجماليات والرصيد في قاعدة البيانات عند كل تغيير. لا تُقبل عملية تحصيل تتجاوز الرصيد المتبقي أو تُسجّل على مسودة غير معتمدة. كما يسجل إنشاء الفاتورة وتحرير المسودة وإصدارها والتحصيل والإلغاء في `platform_audit_logs`.

## اختبارات التنفيذ

اختبر النظام عملياً بإصدار فاتورة اشتراك بقيمة 100 واحتساب ضريبة 5 وإجمالي 105، ثم محاولة تحصيل زائد تم رفضها، فدفعت الدفعة الجزئية 25 ثم الدفعة النهائية 80؛ وكانت الحالة النهائية **مدفوعة** والرصيد **0**. حُذفت بيانات الاختبار بعد التحقق.
